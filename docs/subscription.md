# 订阅与规则

安装完成后，脚本会打印一个订阅地址。把它粘到 FlClash 的「订阅」里，即可直接使用，不需要手动填节点。

## 地址形式

```text
http://<公网地址>:<订阅公网端口>/<随机令牌>/config.yaml
```

令牌是安装时随机生成的 32 位十六进制串，相当于订阅的密码。不要公开它。

## 端口对应关系

订阅服务只监听实例内部的 `127.0.0.1`，必须由云平台的端口转发转出来。

| 用途 | 公网端口 | 实例内部 |
|---|---|---|
| 代理节点 | 由平台决定 | Xray 监听端口 |
| 订阅 | 由平台决定 | 2096（默认） |

脚本会打印实际的订阅地址，直接用它即可。若地址里的公网端口与平台映射不一致，说明该端口没有映射到实例的 2096，需要在平台加一条转发。

## 规则文件

服务器上：

```text
/etc/xray-sub/rules.yaml
```

格式：每行一条规则，必须以 `- ` 开头，`#` 开头是注释。

修改方式两种：

**菜单方式**

```bash
xray-admin
# 选 5 编辑分流规则
```

会自动备份、调用编辑器、校验并重新生成。

**手动方式**

```bash
nano /etc/xray-sub/rules.yaml
xray-sub          # 重新生成
```

FlClash 里下拉刷新订阅即可，不用重启任何服务。

## 规则校验

`xray-sub` 会拒绝生成：

- 有非注释行不以 `- ` 开头
- 规则文件为空
- 生成的订阅缺少节点或规则

校验失败时不会覆盖已有订阅文件，旧的仍然可用。

## 顺序原则

规则从上到下匹配，第一条命中即生效。所以模板按这个顺序组织：

1. 本机、局域网、内网 CIDR → DIRECT
2. 路由器管理页 → DIRECT
3. AI 服务 → PROXY
4. 开发与内容站 → PROXY
5. 国内常用服务 → DIRECT
6. `GEOIP,CN` → DIRECT
7. `MATCH` → PROXY

调整时保持这个顺序，否则会被前面的规则抢先命中。

## 关于把规则放进 Xray

做不到。这些是客户端协议专有的能力：

| 规则类型 | 为什么服务端不行 |
|---|---|
| `PROCESS-NAME` | 服务端看不到你电脑上的进程 |
| `GEOIP,CN` | 依赖客户端 GeoIP 库，服务端只有出口判断 |
| `AND,((DST-PORT,443),(NETWORK,UDP))` | Clash 专有语法 |
| `SUB-RULE` | 需要客户端规则集 |

所以规则必须留在 FlClash 执行。放 VPS 上的意义是：统一管理、一处修改、多设备同步。

## 私密性

订阅文件只包含：

- 节点连接参数（地址、端口、UUID、公钥、shortId）
- 分流规则

**不包含**服务端私钥。已用测试断言检查生成文件里不出现 `private` 字段。

但 UUID 和公钥足以连接你的节点，所以订阅地址等同凭据，不要发到公开场合。

## 取消订阅

```bash
systemctl disable --now xray-sub
rm -rf /srv/sub /etc/xray-sub /etc/systemd/system/xray-sub.service
```

不会影响 Xray 节点本身。
