# 部署细节

本文件只记录通用说明和已做过的验证，不含任何具体实例的 IP、端口或目标站。

## 脚本做的事

`one-click.sh` 会按顺序执行：

1. 检查 root 权限、Debian、systemd、amd64。
2. 收集五项参数：公网地址、公网 TCP 端口、内部 TCP 端口、REALITY 目标、serverName。
3. 安装缺失的工具依赖（`ca-certificates curl openssl unzip jq iproute2 procps`）。
4. 校验目标站：DNS 不指向私网、证书有效、TLS 1.3、ALPN h2、HTTP 状态非重定向。
5. 下载固定版本 Xray，校验 SHA256。
6. 生成配置，用真实 Xray 做 `-test` 校验。
7. 创建 `xray` 系统用户，安装独立 systemd 服务并启动。
8. 导出客户端节点到 `/root/xray-client/node.json`。

不会修改端口映射、防火墙、APT 源、内核参数或系统 DNS。

## 端口怎么填

云平台的端口转发通常有两列：

```text
外部端口（客户端连这个）  →  内部端口（实例内程序监听这个）
```

脚本会分别询问：

- **公网 TCP 端口**：填外部端口。
- **内部 TCP 端口**：填内部端口。

没有 NAT 的 VPS 两个值相同，通常都是 443。有 NAT 的容器/小机必须按平台实际映射填写，否则服务起来了也连不上。

## REALITY 目标怎么选

脚本预置了默认目标 `www.microsoft.com`，也就是第 4、5 项直接回车即可。这个默认值满足：

- 国外站点；
- 支持 TLS 1.3 与 HTTP/2；
- 根路径返回 200，不跳转；
- 证书链完整；
- 与常见 VPS 地域延迟可接受。

脚本每次安装都会**实时复验**，任何一项不满足就停止，不会带着坏目标继续安装。实测确认过该站点在国内网络条件下 TLS 握手可用，但目标站的可用性会随时间变化，所以每次安装都重新检测，而不是把检测结果写死在脚本里。

想换目标时，第 4 项填 `域名:443`，第 5 项填同一域名。不要用 Apple 系域名，Xray 官方日志明确警告这类目标会显著提高 IP 被封概率。

## 密钥与重复安装

- 首次安装生成 UUID、X25519 密钥对和 shortId。
- 重复运行会读取已保存的状态，**不会更换密钥**，客户端配置继续有效。
- 想强制换密钥，需要先删除 `/usr/local/etc/xray/client.json`，这会让所有已导入的客户端失效。

## 回退

安装过程中任何一步失败，脚本会恢复旧的二进制、配置和服务单元，并尽量拉起原服务。备份目录在 `/root/xray-backups/`，权限 700。

自动回退不能保证在异常宿主环境下一定成功，失败后应查看备份目录和 `journalctl -u xray`。

## 验收清单

1. `systemctl status xray` 为 active。
2. `ss -lntp` 能看到内部端口在监听。
3. 用手机流量或另一台电脑导入节点，访问测试地址，确认出口 IP 是这台 VPS。
4. 验证本地直连的站点（NAS、内网、国内服务）仍然直连。
5. 重启服务、重启实例后各验证一次。

未完成这些验证前，不要认为已经长期稳定。

## 已知限制

- 仅支持 Debian amd64 + systemd。
- 128 MB 内存是低配下限，长期高并发需要观察。
- 配置能降低被动识别概率，但不能保证 IP 不被封。
- 日志写入 journald，已设速率限制，但仍需定期检查磁盘。
